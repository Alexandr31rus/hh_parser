# HH Parser

Приложение для поиска вакансий на hh.ru с сохранением статистики
по технологиям и зарплатам. Состоит из веб-интерфейса на Flask и
фонового парсера, который обрабатывает заявки пользователей.

## Возможности

- Регистрация и авторизация пользователей (хеширование паролей
  через PBKDF2-HMAC-SHA512).
- Создание заявок на подбор вакансий: регион + поисковый запрос.
- Фоновый парсер, который по заявке:
  - ищет вакансии через API hh.ru;
  - извлекает технологии из описания и ключевых навыков;
  - считает частоту упоминаний технологий;
  - усредняет зарплаты по грейдам (Junior / Middle / Senior / Unknown);
  - сохраняет результат в JSON-файл.
- История заявок с результатами обработки.

## Технологии

- Python 3.13
- Flask
- SQLAlchemy + SQLite
- requests
- python-dotenv
- uv (управление зависимостями)

## Установка

### 1. Клонировать репозиторий

```bash
git clone <repo-url>
cd HH_parser
```
### 2. Установить зависимости

```bash
uv sync
```

### 3. Настроить окружение

Скопируйте .env.example в .env и заполните SECRET_KEY:
```bash
cp .env.example .env
python3 -c "import secrets; print(secrets.token_hex(32))"
# вставьте полученную строку в .env как SECRET_KEY=...
```

### 4. Настроить конфиг приложения

```ini
[SQLite]
path = sqlite:///../Database/hh_flask.sqlite?check_same_thread=False

[Json]
path = ../FilesWithRequests
```
[SQLite] path — URL базы данных. Относительный путь
разрешается от src/app/.

[Json] path — каталог для JSON-файлов с результатами.
Создаётся автоматически при первом запуске.

### 5. Создать схему БД

```bash
uv run python3 -m src.app.create_db
```
Команда спросит подтверждение, удалит существующие таблицы и
создаст их заново по моделям.

## Запуск

```bash
uv run python3 -m src.app.main
```

Запускаются два процесса:

Flask на http://127.0.0.1:5000 — веб-интерфейс;

фоновый парсер (multiprocessing.Process) — опрашивает
БД на новые заявки и обрабатывает их.

Остановка — Ctrl+C. Парсер завершается вместе с Flask
(через finally вокруг app.run()).

## Использование

1. Откройте http://127.0.0.1:5000/.

2. Зарегистрируйтесь (/register) и войдите (/login).

3. Создайте заявку на /requests: укажите регион и поисковый
запрос (например, «Москва» и «Python»).

4. Дождитесь обработки — статус заявки в истории сменится
с «Инициализирован» на «В обработке» и затем на «Завершен».

5. Откройте /history и кликните «Смотреть» у нужной заявки,
чтобы увидеть результаты: топ технологий и средние зарплаты
по грейдам.

## Статусы заявок

| Код | Название | Значение |
| :--- | :--- | :--- |
| 0 | Инициализирован | Заявка создана, парсер её не взял |
| 1 | В обработке | Парсер сейчас ищет вакансии |
| 2 | Завершен | Результаты готовы, файл создан |

## Известные ограничения

С апреля 2026 года метод GET /vacancies возвращает
403 Forbidden без авторизации:

```json
{"errors": [{"type": "forbidden"}]}
```

Для работы парсера нужен один из вариантов:

Официальный токен — регистрация приложения на
dev.hh.ru, подтверждение аккаунта
работодателя, модерация.

Cookie залогиненной сессии — извлечь hhtoken из браузера
и передавать в requests. Временное решение, не для
продакшена.

Без этого парсер будет получать 403 и возвращать пустые
результаты.

## ⚠️ flask_table несовместима с Flask 3.x

flask_table (последняя версия 2020 года) импортирует
Markup из flask, который переехал в markupsafe начиная
с Flask 2.3. Решения:

откатить Flask до <2.3 (не рекомендуется);

monkey-patch: flask.Markup = markupsafe.Markup до импорта
flask_table;

отказаться от flask_table и рисовать таблицу вручную в
Jinja2 (рекомендуется).

## ⚠️ Ограничение выборки

Парсер обрабатывает не более 50 вакансий на заявку
(l_urls[0:50] в process_request.py). Ограничение захардкожено.

Безопасность
Не коммитьте .env — там SECRET_KEY. В репозитории
должен быть только .env.example с заглушкой.

Не коммитьте hh_config.ini с реальными путями, если
используете абсолютные пути. Держите hh_config.example.ini.

Не коммитьте файлы БД (*.sqlite). Они в .gitignore.

Пароли хранятся в виде хеша (PBKDF2-HMAC-SHA512, 100k
итераций, уникальная соль). В открытом виде — никогда.

## Разработка

### Пересоздать БД

```bash
uv run python3 -m src.app.create_db
```

Уничтожает все данные и создаёт схему заново. Только для
локальной разработки.

### Проверить, что парсер работает

```bash
# процесс жив?
ps -ef | grep spawn_main | grep -v grep

# статусы заявок
sqlite3 src/Database/hh_flask.sqlite \
  "SELECT id, status, vacancy_number FROM requests ORDER BY created DESC LIMIT 5;"

# результаты
ls -la src/FilesWithRequests/
```
